# Languages (English and French)

Everything a seller sees exists in English and French. Prospect-facing text (viewer, follow-ups) has its own wider list of languages in `app/src/lib/closing/i18n/`.

## App (`app/`)

- [next-intl](https://next-intl.dev), without a locale in the URL.
- The language is `User.locale` ("en" | "fr"). Without a session, the `NEXT_LOCALE` cookie is used, then the browser, then English. Resolved in `src/i18n/request.ts`, helpers in `src/i18n/locale.ts`.
- Text lives in `messages/{en,fr}/<namespace>.json`, one file per area (`deal`, `documents`, `settings`, `onboarding`, …), registered in `src/i18n/messages.ts`. A new namespace needs a line there.
- Keys are type-checked: `t("missing")` fails `tsc`. `src/i18n/messages.test.ts` checks that en and fr have the same keys.

Using it:

- Client component, or a server component that isn't async: `const t = useTranslations("deal.header")`, `const locale = useLocale()`.
- Async server component, server action, route handler: `await getTranslations("deal.header")`, `await getLocale()` from `next-intl/server`.
- Code with no request (Trigger.dev tasks, emails, alerts): `getSellerLocale(userId)` from `src/lib/seller-locale.ts`, then `getTranslator(locale)` from `src/i18n/messages.ts`. Server only: it bundles every message.
- Dates and numbers: `src/lib/format.ts` takes a locale. For a raw `Intl` call, use `INTL_LOCALE[locale]`. Never hard-code `"fr-FR"`.
- Enum labels (deal status, tier, alert type…) are in the `labels` namespace, keyed by the enum value: `tl(\`dealStatus.${status}\`)`.
- AI prompts stay in English. Only the output language follows the seller (`src/lib/closing/ai/seller-language.ts`).
- Route names are English. `next.config.ts` redirects the old French ones.

Writing copy: the French addresses the user as "vous". The English is plain and direct, addressing the user as "you", in natural SaaS wording rather than a literal translation. Vocabulary: lien → link, lecteur → reader, relance → follow-up, proposition → proposal, devis → quote, pilote automatique → Autopilot, Réglages → Settings, Équipe → Team.

## Chrome extension and Outlook add-in

- All text lives in `extension/src/lib/copy.ts`, as one table per language. The file stays pure because the Outlook runtime imports it.
- The language comes from `navigator.language`, or `Office.context.displayLanguage` in Outlook. Calls to `/api/ext/*` send it as `Accept-Language`.
- Manifest strings: `extension/public/_locales/{en,fr}/messages.json` for Chrome. In `outlook/manifest/manifest.xml`, English is the default and French is added with `<Override Locale="fr-FR">`.

## Landing (`landing/`)

- `/en/...` and `/fr/...`, with slugs translated per language (`src/i18n/routing.ts`). Old French URLs return 301 to `/fr`.
- Text: `messages/{en,fr}.json`. Legal pages: `src/content/*.{en,fr}.tsx`.
- Links to the app carry `?lang=`. The app's proxy turns that into the language cookie.
